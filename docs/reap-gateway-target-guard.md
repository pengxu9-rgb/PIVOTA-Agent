# Isolated stored-catalog gateway target guard

`node src/rehearsal/storedGateway.js` is a separate preparation entrypoint. It performs configuration and actual PostgreSQL identity/privilege/schema/marker verification before importing the full server module. It then requires the separately reviewed stored-catalog suppression policy. A missing policy refuses launch. The production command remains unchanged; this wrapper does not run the production `require.main` startup jobs or migrations.

The proposed target is hardcoded in `catalogTargetGuard.js`: staging database `reap_rehearsal_20261002_01a0f`, host10.122.0.3:5432, catalog actor `reap_rehearsal_01a0f_catalog`, migrator ownership. A dedicated-instance decision is still required: the existing shared instance has PUBLIC access to other databases. This guard refuses that topology; it does not revoke existing permissions. A newly approved host must be pinned in a reviewed source commit. No CLI/environment target override exists.

Require exact preparation/master/create flags, an explicitly exported stored-profile flag, `SEARCH_BUDGET_REQUIRE_MARKER=true` and a numeric `projects/pivota-staging/secrets/reap-rehearsal-20261002-01a0f-catalog-dsn/versions/<number>` reference. DSN query/options, whitespace, alternate actor/database/host/port and ambient PG configuration refuse before loading the driver. Do not print DSN/password values.

The actual connection must match database, server address/port, current/session actor and database/public-schema owner. The role must have no superuser, role/database creation, replication, RLS bypass, broad membership, CREATE/TEMP, or cross-database CONNECT. Its default transaction mode must be read-only. Dotenv files in both the package root and working directory are refused before import; guarded database, secret, profile, private audience/target and agent identity bindings and remote serving-index settings are locked against changes before loading server code. Only SELECT on the10 stored-catalog relations and immutable fixture marker is accepted; other readable relations, table/column writes, unknown privileges (including PG17 MAINTAIN), grant options, extra schemas (including `pgx`, with a literal system-schema prefix check) and executable user security-definer functions refuse. All sequence grants (includingUSAGE/UPDATE/SELECT/grant-option) are denied and user sequences must belong to the scoped migrator. The schema must match all278 original column types/typmods/nullability entries, including canonical election. The marker must identify the scoped fixture and original backend base.

This is a database target/permission boundary, not a complete network sandbox. Deployment still needs reviewed private per-hop IAM, receiving-service origins, numeric secret bindings, the separate stored-catalog suppression policy and independent egress restrictions. No existing service/IAM/worker/traffic changes are included. The unchanged local checkout rehearsal remains separate.

Tests use a new disposable loopback PostgreSQL55439 cluster with empty synthetic tables constructed from original metadata; no product/buyer rows or historical fixture database are copied.23 unit checks and25 real PostgreSQL checks pass, including grant/role/schema/marker/type/cross-database negatives with cleanup and re-probe. PG15 executes the actual ACL query; its privilege-name allowlist is version-safe, while a real PG17 MAINTAIN grant is a separate deployment-version check.
