# Reviewed seller evidence for the relationship graph

This lane stores source-grounded seller facts for the graph in `public.relgraph_reviewed_seller_evidence`. It is separate from the public Pivota Insights KB. The graph bundle retains `evidence_profile: seller_only`, low overall confidence, `graph_only: true`, and `public_insights_eligible: false`. Source review verifies what a page says; it does not establish independent efficacy, suitability, an endorsement, or a good dupe. Relation approval and serving safeguards remain unchanged. The existing public-card replacement classifier still applies to public Insights and rejects these minimal seller bundles.

## Construct and publish bounded evidence

1. Freeze at most 17 exact current listings and their authoritative HTTPS PDP URLs in memory. Obtain one genuine page response per selected exact URL through the reviewed acquisition helper. Its response-completion time is `source_observed_at`; extraction-generation, review, and database-storage times do not refresh source freshness. Stop on redirects, challenges, market/variant/identity drift, missing substantive source facts, or an ambiguous ingredient section.
2. Call `prepareSellerInsights(actualCapture, {nowMs})`. It checks the private response Buffer (at most 2 MiB), its SHA-256, exact source-capture binding, and the retained description/usage against actual page text. The bounded excerpt must contain every retained fact. The deterministic draft contains only the source title, grounded product brand, description and optional usage; no benefits, watchouts, recommendations or external signals are generated. The source observation must be at most 45 days old at publication.
3. Have the independently reviewed operator obtain actual GPT and Gemini claim assessments of the frozen source excerpt and all draft claims. Each review must supply a distinct real receipt ID, actual review time, provider, pinned model, `packet_sha256`, source/bundle hashes, decision, confidence, and every exact supported quote. Optional `provider_response_sha256` is a strict hash, never a response payload. Both providers must approve with confidence at least 0.90 and support every claim, including the exact product brand. The graph canonical brand comes from this reviewed page fact; a retailer hostname must never substitute for it. Disagreement becomes `human_review`; matching rejection or uncertainty becomes `evidence_hold`. This module validates supplied proof; it does not call providers or authenticate their receipts itself.
4. Call `makeGraphSellerEvidence(prepared, reviews, {nowMs})`. Only an approved outcome includes a `record`. The complete draft and claim set are rederived from the captured source at the original draft time; adding an unreviewed claim or private payload is rejected even if a caller recomputes hashes. Capture, review, source and claim metadata are allowlisted and bounded. Recursive canonical object-key hashing survives PostgreSQL JSONB reordering while retaining array order. Raw response bytes and model responses are never included in the durable record.
5. Apply migration 063 through the independently reviewed schema process on the same main database used by graph hydration. Verify columns, proof-marker checks, exact-identity/time index, and UPDATE/DELETE/TRUNCATE refusal triggers. Runtime code performs no DDL. Validate the schema in a rollback-only transaction before first publication. The optional table probe preserves existing behavior when the table is absent.
6. Dry-run `appendGraphSellerEvidence({pool, records, rawSourceBodies, nowMs, apply:false, rebindExactListing})`. Raw Buffers travel in a separate array with exactly the same membership as records. The required callback `rebindExactListing({client,record})` must read the exact current catalog/seed listing and its authoritative source references using the supplied transaction client, rather than returning an old manifest or using another pool. The writer rechecks the complete immutable identity and current URL inside one SERIALIZABLE transaction, with sorted identity advisory locks and bounded timeouts.
7. After source/operator review and green CI, invoke the same writer with `apply:true`. It appends at most 17 rows to its own store. It never writes the public Insights KB, ingredient KB, product catalog, or graph edges. Identical proof IDs are idempotent. A newly captured version of identical facts can append without altering history; changed facts require a separate reconciliation decision. Existing protected, human or denied public evidence is inspected on the same client in raw form, including legacy snake/camel aliases and alternate document shapes. A protected/denied collision, conflicting historical facts, or a five-row scan sentinel holds the entire batch.

```js
const evidence = require('./src/services/relationshipReviewedInsightsRefresh');
const prepared = evidence.prepareSellerInsights(actualCaptureInMemory, {nowMs});
const outcome = evidence.makeGraphSellerEvidence(prepared, actualProviderReviews, {nowMs});
if (outcome.status === 'approved') {
  const receipt = await evidence.appendGraphSellerEvidence({
    pool, records: [outcome.record], rawSourceBodies: [actualCaptureInMemory.raw_source_body],
    nowMs, apply: false, rebindExactListing: reviewedTransactionBoundListingResolver,
  });
}
```

Errors before a commit attempt roll back. If the COMMIT acknowledgment is lost, the writer returns `publication_outcome_unknown`, the durable evidence IDs, null write counts and `retry_allowed:false`, discarding the uncertain connection. Establish whether those exact IDs and fingerprints persisted in a subsequent read-only transaction before considering any retry. Never claim that an uncertain commit rolled back.

## Hydration and measurement

`loadProductIntelKbRows` adds this optional lane to existing graph hydration. It filters exact identity before the existing per-target four-row plus sentinel cap and checks the complete identity again during candidate merge. The global limit remains bounded. Invalid proof, flat-column disagreement, or wrong market/platform/variant cannot lend evidence to another listing. Raw protected or denied public evidence suppresses colliding graph-only rows before ranking even when the public normalizer would omit it. Existing human/protected public Insights take priority over newer graph-only assistant evidence.

Hydration uses actual `source_observed_at` as its freshness clock and retains immutable evidence/dual-review linkage. Old observations remain old. A successful append establishes durable reviewed source evidence; a subsequent bounded graph evaluation is still needed to establish whether recall or alternative/dupe eligibility improved. Do not export private facts, page bytes, identities, URLs, credentials, or model responses in operator logs or aggregate receipts.
