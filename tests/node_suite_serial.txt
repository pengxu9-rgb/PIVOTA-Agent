# Suites that assert on TIMING or CONCURRENCY and must not compete with the batch for CPU.
# They are gated exactly like every other suite — this file changes HOW they run, never
# WHETHER. That distinction is the whole point: the alternative was quarantining them, which
# would have removed real coverage to buy a green run.
#
# The mechanism. Each of these builds a deliberately never-settling promise
# (`() => new Promise(() => {})`) and asserts that a deadline or concurrency limiter reacts
# to it. Run alongside ~330 other suites, node's runner reports them `cancelledByParent`
# with "Promise resolution is still pending but the event loop has already resolved": under
# contention the file's own loop drains before the pending work is observed. Run with
# `--test-concurrency=1` they pass — verified for all three, and it is also why they pass
# when a developer runs one file by hand and looks fine.
#
# NOT a pattern match. 12 gated suites contain a never-settling promise and seven of those
# ran green under the old allowlist for months, so the pattern alone does not predict this.
# Only suites CI has actually cancelled are listed here.
#
# Each entry earned its place from an observed CI cancellation:
#   acpBuyerIntake                            5 LOAD tests, run 34519374321
#   find_products_beauty_discovery_local_mainline   1 wall-clock test, run 34510762322
#   aurora_bff_reco_relevance                 1 concurrency test, run 34520405621 (and it
#                                             PASSED the run before — intermittent, which is
#                                             why one-at-a-time quarantining never converges)
